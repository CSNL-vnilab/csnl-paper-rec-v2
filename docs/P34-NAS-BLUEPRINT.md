# P34 — NAS natural-language index + auto-routing blueprint

**Status:** DESIGN (batch09 synthesis of D1-index / D2-router / D3-explore). No code changed,
no DB written, no send. Everything below is implemented behind the existing dry-run/`--apply`
operator gate.
**Goal (operator, 2026-07-24):** (1) any model can retrieve NAS files by **natural language**
at any time; (2) an automation pipeline **routes newly-uploaded** PB/GRM/MM slides, experiment
code, and manuscripts to the right consumer via MCP/API.
**Hard constraint 1 — efficiency:** a **generalizable index on a few dimensions**
(owner-initial · kind · date · a filename-cheap title/DOI), **not** a per-file hardcoded catalog.
Record conventions, not contents. One rule over ten special cases.

**Hard constraint 2 — the NAS is read-only and its paths never leave the lab** (operator,
2026-07-24, inviolable):
- **Read-only share.** The indexer and the router `stat`/`listdir` only — they NEVER open, move,
  rename, delete or write a byte on the NAS. Every write lands in Postgres (the lab's own Supabase).
- **No path egress.** A NAS path — `smb://…`, an absolute `/Volumes/…`, or even a share-relative
  `MM/JOP/…` — must **never** be sent to anything outside the lab: not in an outbound email/Notion,
  not to a third-party API, not to a cloud-hosted model. The `nas-index` MCP is **LOCAL/stdio only**
  and is served **only to models running on-lab**; a caller that could relay a result off-lab is not
  a permitted consumer. §2 and §4 are constrained accordingly — "exposing it widely" earlier meant
  *within the lab*, and this section overrides any looser reading. Store relative paths internally,
  never emit them externally.

Sources: `state/archive/_explore/batch09/{D1-index,D2-router,D3-explore}.md`.

## 0. Shape in one paragraph — ONE walk, two outputs

There is exactly **one process that touches the NAS**: a thin, catalog-driven **indexer**
(`index_nas.py`) that `safe_walk`s four research subtrees, `stat`s each file (never `open`s one),
and UPSERTs a **locator row** into `csnl_paper_rec.nas_index` — *where · what-kind · who · when*
plus a filename-cheap `title_or_doi`. That table is **both** the natural-language retrieval
surface (read by a strictly read-only `nas-index` MCP) **and** the change feed for routing.
The **router** never walks the NAS a second time: it reads the rows the last index run just wrote
(keyed on `run_id`) and dispatches each routable one to its consumer — slides back into the
**existing** `ingest_grm_nas.py` ingester (`archive_meeting_materials`), code + manuscript to a
pointer table (`archive_nas_artifacts`). The unattended cron calls plain Python end-to-end (no LLM,
DECISIONS-v3); the MCP layer is the attended facade over the same code. Net standing complexity:
**one walker, one watermark, three new DB objects, one broadly-shared read-only MCP.**

```
                         ┌───────────────── the ONLY NAS reader ─────────────────┐
   Wed cron / operator ! │  index_nas.py  (safe_walk → stat-only → classify)     │
                         └───────────────┬───────────────────────────────────────┘
                                         │ UPSERT locator rows (run_id stamped)
                                         ▼
                        csnl_paper_rec.nas_index  ◀── read-only ── nas-index MCP  ── any model (NL)
                                         │                          (nas_search / nas_get)
                        run_id change feed │ (rows this run wrote)
                                         ▼
                 route_new_nas_files.py  (DB-delta dispatcher, plain Python)
                    ├─ pb/grm/mm  → ingest_grm_nas.py --date  → archive_meeting_materials  (REUSE)
                    ├─ experiment_code → route_code()          → archive_nas_artifacts (pointer/dir)
                    └─ manuscript      → route_manuscript()    → archive_nas_artifacts (pointer/file)
```

**Why one walk, not two (D1 + D2 reconciled):** D1 and D2 each proposed a watermark table and a
NAS walk. Collapsing routing into a *consumer of the index delta* removes the second walk and the
second watermark entirely — the router's change feed is simply `nas_index_runs.run_id`, and its
only NAS touches are the bounded per-pointer enrichments (a manuscript first-page DOI sniff, a code
`.git/config` read) on the specific files it routes. This is the single biggest standing-complexity
cut in the synthesis and it directly serves the efficiency constraint.

## 1. The index — `nas_index` table + incremental indexer

### 1.1 Table DDL (additive · idempotent · reversible; operator-run `!`)

PK = `sha1(nfc(rel_path))` over the **share-relative** path (never `/Volumes/CSNL_new-1/…`, which
drifts by mount order). Small **fixed** column set; `subtree`/`ext` are generated by **one rule
each**, not bespoke per-file fields.

```sql
-- state/migrations/<date>_p34_nas_index.sql
BEGIN;
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE TABLE IF NOT EXISTS csnl_paper_rec.nas_index (
  path_sha1     CHAR(40) PRIMARY KEY,                 -- sha1(nfc(rel_path)); mount-independent
  rel_path      TEXT NOT NULL UNIQUE,                 -- NFC, share-relative
  subtree       TEXT GENERATED ALWAYS AS (split_part(rel_path,'/',1)) STORED,
  ext           TEXT GENERATED ALWAYS AS (lower(substring(rel_path FROM '\.([^./]+)$'))) STORED,
  kind          TEXT NOT NULL CHECK (kind IN
                  ('pb','grm','mm','paper','experiment_code','manuscript','data','other')),
  owner_initial TEXT CHECK (owner_initial IS NULL OR owner_initial ~ '^[A-Z]{2,8}$'),
  event_date    DATE,                                 -- folder date preferred; NULL when none cheap
  title_or_doi  TEXT,                                 -- filename-cheap ONLY; NULL when absent
  bytes         BIGINT,
  mtime         TIMESTAMPTZ,
  is_dir        BOOLEAN NOT NULL DEFAULT FALSE,        -- names-only shallow dirs (fMRI_DICOM/SNUBIC)
  deleted_at    TIMESTAMPTZ,                           -- soft-delete: unseen on last full walk of scope
  run_id        BIGINT,                                -- last run that WROTE this row = router change feed
  indexed_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ix_nas_index_facets
  ON csnl_paper_rec.nas_index (kind, owner_initial, event_date) WHERE deleted_at IS NULL;
CREATE INDEX IF NOT EXISTS ix_nas_index_trgm
  ON csnl_paper_rec.nas_index USING gin
     ((coalesce(rel_path,'') || ' ' || coalesce(title_or_doi,'')) gin_trgm_ops);
CREATE INDEX IF NOT EXISTS ix_nas_index_mtime
  ON csnl_paper_rec.nas_index (mtime) WHERE deleted_at IS NULL;

CREATE TABLE IF NOT EXISTS csnl_paper_rec.nas_index_runs (
  run_id      BIGSERIAL PRIMARY KEY,
  started_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at TIMESTAMPTZ,
  scope       TEXT NOT NULL,        -- 'full' | 'GRM/2026,MM,Memory,people'
  mtime_high  TIMESTAMPTZ,          -- max(file mtime) seen = incremental cursor (the ONE watermark)
  files_seen  INT, rows_upserted INT, rows_deleted INT,
  volume_root TEXT,                 -- resolved /Volumes/… (audit only; never a PK input)
  ok          BOOLEAN
);
COMMIT;
```

Each column earns its place: `kind/owner_initial/event_date` are the three facets every NL query
reduces to; `rel_path || title_or_doi` is the free-text surface; `bytes/mtime` are free (already in
the `scandir` stat); `is_dir` lets `fMRI_DICOM`/`SNUBIC` be *named* without indexing their millions
of DICOMs; `deleted_at` reconciles a deleted deck whose orphan `~$` lock stub survives, without a
hard delete; `run_id` is the router's change key (§3).

### 1.2 Indexer — `scripts/archive/index_nas.py` (operator-gated `!`)

A **thin loop over `safe_walk`** — symlink-loop / recycle-bin prune / `fMRI_DICOM`+`SNUBIC`
shallow-list / EACCES-tolerance are already handled in `_common.safe_walk()`. Every per-file
decision defers to `config/nas_catalog.json`, so a new naming convention is a **catalog edit,
never a code change**.

```
base = ingest_grm_nas._resolve_nas_base(...)              # resolve at runtime; never hardcode volume
for dirpath, dirnames, filenames in safe_walk(base, ...):
    if top_segment(dirpath) not in {'GRM','MM','Memory','people'}:   # scope allow-list (§1.4)
        dirnames[:] = []; continue
    for name in filenames:
        rel = nfc(relpath(join(dirpath,name), base))
        if is_ignorable(name):        # catalog ignore_rules: ~$ lockstub / dotfile / AppleDouble / ext∉allow
            continue
        st  = os.stat(join(dirpath,name))       # stat ONLY — never open()
        rows.append(classify_row(rel, dirpath, name, st))   # §1.3
    flush_upsert(rows)                          # exec_many, chunked, stamps run_id
```

- **owner_initial:** whole-token match of the NFC stem against catalog `initials{}` aliases +
  `korean_name`, rejecting `matching_policy.noise_tokens`; lab-wide bundles → `NULL` (never fabricate
  a presenter). For code/manuscript, owner is the **containing `{INIT}` folder**, not the filename
  (D3: filename author-surname clusters — `LeeYeoLee`, `GuEtAl`, `KimEtal` — do **not** map to a lab
  initial).
- **event_date:** catalog `date_token_forms` in order, **folder date preferred** over filename date;
  `NULL` for code (D3: files are not date-stamped) and for date-less names.
- **title_or_doi:** cheap **filename-stem-only** extraction (`_DOI_RE`; `Author_Year_Title`;
  Zotero `X et al. - Year -` / `X 등 - Year -`; BYL author-year; SK topic-slug). `NULL` when the
  filename carries no identity. **No file is opened to enrich it.**

### 1.3 `kind` — one ordered 8-value rule set (path-segment → ext-class → catalog `classify()`)

First match wins:

1. segment `…/Code/…` **or** (`subtree=people` + code-ext `.py .ipynb .m .r .mjs .js .sh .c .cpp .jl .stan`) → **experiment_code**
2. segment `…/Data/…` | `…/Results/…`, or data-ext `.nii .mat .npy .csv .h5 .zip` → **data**
3. `subtree=MM` → **mm** (reuse `classify()` for presenter/date; kind fixed by folder)
4. `subtree=GRM` → `ingest_grm_nas.classify()` → **pb** | **grm** (its deviation handling comes free)
5. **manuscript folder-token** (`Manuscript|writing|Writings|submissions|Revision|Thesis`) **OR**
   filename token (`Manuscript_|Merged|Abstract|Introduction|Method|Discussion|rev|reply|Revised|EtAl|연차보고서`),
   ext ∈ `{.pdf,.docx}` → **manuscript** *(D3 precedence — see the `.docx` trap in §4)*
6. `subtree=Memory` + `Papers/`|`Context/` + `.pdf`, or a Zotero-export shape → **paper**
7. `Memory/Reports/(Report) by {YYYY.MM.DD}.pdf` → **other** (lab report; no owner) *(D3 §2e)*
8. else → **other**

`experiment_code` is the only kind outside the catalog's slide vocabulary and is still **one rule**
(`Code/` segment ∪ code-ext), not a hardcoded file list. `pb/grm/mm` inherit every
never-anchor / never-substring / never-coin-a-presenter guard from `classify()`.

### 1.4 Scope allow-list + prune knobs (bounds the row count)

Descend **only** `GRM`, `MM`, `Memory`, `people`. Everything else at root (`Server`, `Grant`,
`GPU`, `Photo`, `PACS…`, `group-volume`, `AI_workspace`, `#recycle`/`@Recycle` — catalog
`_ops_and_junk`) is not walked. Two small standing knobs from D3:
- **toolbox-prune** (do NOT attribute vendored libraries as the researcher's code):
  `{bads-master, mcmcstat, dynamic_bias, Gu_et_al}` living inside `Code/`.
- **privacy-exclude** (never surfaced in NL): `people/*/Private`, `people/JOP/박준오 개인정보`.

This caps the index at **~tens of thousands of rows** (≈4.9k papers + ~160 MM + ~500 GRM + Context +
code/data), never the 86 TiB / millions-of-DICOM share.

### 1.5 Incremental refresh (cheap to keep current)

- **Watermark:** `nas_index_runs.mtime_high = max(file mtime)` of the last successful run per scope.
- **Quick refresh (default):** walk only mutable subtrees (`GRM/<year>`, `MM`, `Memory/*/Context`,
  `people`); UPSERT only when `path_sha1` is **new** or `mtime > row.mtime`. `Memory/Papers`
  (≈4.9k, near-static) only on `--full`.
- **No-churn UPSERT:** `ON CONFLICT (path_sha1) DO UPDATE … WHERE mtime/kind IS DISTINCT FROM
  EXCLUDED OR deleted_at IS NOT NULL` (unchanged rows are not rewritten).
- **Soft delete:** collect the in-memory `path_sha1` seen-set per fully-walked subtree (~40 B × ~30k
  ≈ 1.2 MB) → one `UPDATE … SET deleted_at=now() WHERE subtree=ANY($scope) AND path_sha1 <> ALL($seen)`.
- Walk stays **≤2 concurrent NAS readers** (really one sequential walker), **one `stat` per file,
  zero `open`**, never re-mount / re-auth.

## 2. NL-retrieval MCP — `nas-index` server (strictly read-only)

Registered exactly like `paper-search` in `.mcp.json`:
```json
"nas-index": { "command": "python3", "args": ["-m", "scripts.mcp.nas_index_server"], "env": {} }
```

**Read-only over the DB** (`query_json` only): the server **never walks the NAS, never writes, never
returns file bytes.** It translates NL → a **parameterised** SELECT over `nas_index` (fixed template;
the free-text `query` is bound as a `%s` trigram/ILIKE param — no raw SQL, no string-built WHERE).

```
nas_search(query: string,
           kind?:  'pb'|'grm'|'mm'|'paper'|'experiment_code'|'manuscript'|'data'|'other',
           owner?: string,           # 'JOP' | '박준오' | 'Joonoh' → catalog alias map → INIT
           since?: date, until?: date, limit?: int = 20)
  → { results: [ { rel_path, path,   # path = volume resolved AT CALL TIME (ephemeral, not stored)
                   kind, owner_initial, event_date, title_or_doi, bytes, mtime } ],
      total_matched: int }

nas_get(path? | path_sha1?)
  → { rel_path, path, kind, owner_initial, event_date, title_or_doi, bytes, mtime, exists: bool }
```

Deterministic NL handling inside the server (no LLM): owner words → INIT via catalog aliases;
kind words ("slides"→pb/grm, "paper blitz"→pb, "milestone"→mm, "draft/manuscript"→manuscript,
"code/script"→experiment_code) → `kind`; relative-time words → `since/until`; residual text →
trigram ILIKE over `rel_path || title_or_doi`. Always `WHERE deleted_at IS NULL`,
`ORDER BY event_date DESC NULLS LAST`. `nas_get` re-resolves the current mount and `stat`s the one
file to confirm existence, then **hands back the path** for a NAS-capable caller to open under the
concurrency rules — it does not read or stream content. (Optional third tool `nas_stats()` →
counts by kind/owner for orientation.)

**This is the broadly-shareable surface** that satisfies "any model, natural language, anytime" —
and because it is read-only over a locator table, exposing it widely carries no write/NAS risk.

## 3. Auto-routing pipeline — `route_new_nas_files.py` (DB-delta dispatcher)

### 3.1 Trigger — a **local** cron on the mount host (honestly, nothing else can reach the NAS)

The NAS is LAN-only SMB (`147.47.70.15`), mounted per-user mode-700. A cloud runner (Vercel /
GitHub Actions) **has no route to the LAN and cannot mount the share** — so the trigger MUST live on
the **same lab Mac** that runs the P23/P31 launchd crons.
- `cron/com.csnl.paper-rec.nas.plist` — `StartCalendarInterval` (piggy-back the Wednesday routine)
  + `RunAtLoad` catch-up + once-per-window guard (`state/nas_last_run`, mirroring
  `run_weekly_cron.sh`'s `state/p23_last_build_week`).
- **Deployment prerequisite (memory `macos-launchd-tcc-fda`):** the launchd runner needs **Full Disk
  Access**, or `~/Documents`+SMB jobs die `exit 126 "Operation not permitted"`. This killed the v3
  crons; it is a config prerequisite, not a code issue.
- Gate behind an opt-in marker `state/.NAS_ENABLED` (separate from `.P23_ENABLED` / `.CRON_ENABLED`)
  so it stays dormant until the operator turns it on.

Cron tick = **index then route, chained**:
```
index_nas.py --refresh   → prints run_id   (rc: 0 ok · 3 NAS-unmounted → do NOT mark done, retry)
route_new_nas_files.py --run <run_id> --apply
```
The cron hard-gates: mark `nas_last_run` only on `rc∈{0}`; if the index step fails, the route step
is skipped (build&&send gate idiom).

### 3.2 Classification — location first, then the EXISTING `classify()` (no parallel classifier)

The router adds **zero** filename logic — `kind` is already on the `nas_index` row from §1.3. It
reads `nas_index WHERE run_id = <this run> AND deleted_at IS NULL AND kind IN
('pb','grm','mm','experiment_code','manuscript')` and dispatches on the stored `kind`. Manuscript-
vs-paper disambiguation and the `.docx` trap were already resolved at index time via the catalog
(`ignore_rules.not_material_but_valuable.manuscripts` used as **data**, D3 §2d precedence).

### 3.3 Per-kind targets

**(a) `pb`/`grm`/`mm` slide → the EXISTING ingester, no fork.** Collect the distinct `event_date`s
among the new slide rows and invoke the P31 script per date:
```
! python3 scripts/weekly/ingest_grm_nas.py --date <YYYYMMDD> --apply   → archive_meeting_materials
```
This reuses `classify()`, the Notion schedule enrich, `UNIQUE(nas_path)` idempotency and the tri-state
exit codes **verbatim**. The router never writes `archive_meeting_materials` itself.
*MM caveat (open question, §5 / decisions):* MM decks are `MM/<INIT>/MM260714_JOP.pptx` — date in the
**filename**, not a date-folder, and today's ingester is date-*folder* driven. Preferred fix =
**extend, not fork** `ingest_grm_nas` with a `kind='mm'` + MM scan mode writing the same table;
alternative = leave MM to presence-only (`check_materials.py`).

**(b) `experiment_code` → pointer recorder (one row per `Code/` dir / repo root).** A repo is
thousands of files; per-file indexing is exactly the forbidden "hardcode every peripheral fact." So
`route_code(nas_path, owner, project)` UPSERTs **one** `archive_nas_artifacts` row —
owner/project from the **folder** name (batch02 N4: the `initial` field is wrong 13/48 — key on the
path, never the field); `git_remote` from `.git/config` **if present** (the single cheap enrichment
that lets a consumer clone off-NAS); `last_mtime`. Accepts depth-1 flat (`MSY/`, `KY/`) and depth-2
(`JOP/GranRDT/Code/`). **Not stored:** per-file listings, source, line counts, embeddings.

**(c) `manuscript` → per-file recorder (bounded, each matters).** `route_manuscript(nas_path, owner)`
UPSERTs `archive_nas_artifacts` `kind='manuscript'` with `title_guess` (filename), `doi`
(`_common.norm_doi` of any DOI in the name, or one small first-page sniff via `extract_doi_from_text`),
`last_mtime`. **Not stored:** full text, abstract, section index — a pointer + title + DOI is enough
to hand the file to a downstream consumer.

Both new kinds share **one** discriminated table:
```sql
CREATE TABLE IF NOT EXISTS csnl_paper_rec.archive_nas_artifacts(
  artifact_id   BIGSERIAL PRIMARY KEY,
  kind          TEXT NOT NULL CHECK (kind IN ('code','manuscript')),
  owner_initial TEXT CHECK (owner_initial IS NULL OR owner_initial ~ '^[A-Z]{2,8}$'),
  project       TEXT,                    -- {PROJECT} folder, NULL for flat researchers
  nas_path      TEXT NOT NULL,           -- the Code/ dir (code) or the file (manuscript)
  filename      TEXT,
  title_guess   TEXT,                    -- manuscript only, from filename
  doi           TEXT,                    -- manuscript only, via _common.norm_doi
  git_remote    TEXT,                    -- code only, from .git/config if present
  last_mtime    TIMESTAMPTZ,
  ingested_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  raw_jsonb     JSONB,                   -- {ext_hist?, file_count?} only if cheap
  UNIQUE (nas_path)
);
```

### 3.4 Idempotency — three independent layers, any one sufficient

1. **`run_id` change feed** — the router only processes rows the last index run wrote; already-routed
   rows are not revisited.
2. **`UNIQUE(nas_path)` + `ON CONFLICT DO UPDATE`** on both targets (`archive_meeting_materials`
   existing, `archive_nas_artifacts` new) — a file seen twice self-heals in place, never duplicates.
3. **Index-refresh overlap** re-sees a mid-write file next run; layer 2 makes that a no-op.
Lock-stub / AppleDouble / dotfile / non-allow-list entries never reach `nas_index` at all
(dropped at index time by catalog `ignore_rules`), so no phantom can route.

### 3.5 Failure isolation

Per-file `try/except` → dead-letter JSONL (`state/archive/_tmp/nas_router_deadletter.jsonl`), batch
continues. `safe_walk(on_error=…)` turns an unreadable subtree into a counted warning, not a crash.
NAS-unmounted (rc=3) keeps the watermark and retries; mounted-but-empty (rc=0) marks done. The router
is **one sequential reader**, uses the already-mounted share via `_resolve_nas_base()`, and **never
mounts or re-authenticates** (the NAS auto-bans repeat logins).

### 3.6 MCP for routing — optional attended facade, NOT the unattended path

The unattended cron calls the plain-Python `route_*` functions **directly, no MCP, no LLM**
(DECISIONS-v3). A `nas-router` stdio MCP (`route_meeting_material` / `route_code` /
`route_manuscript` + `nas://watermark` resource) can wrap the *same* functions for an attended
operator session — but because those tools **write**, it is **not** part of the broadly-shared
surface and its `.mcp.json` registration is deferred (decision item). The read-only `nas-index` MCP
(§2) is the only server exposed widely.

## 4. EFFICIENCY — what is deliberately NOT stored (and why)

The operator's hard constraint: *"지나치게 하드코딩하거나 지엽적인 정보를 모두 기록하면 토큰이
낭비되므로 efficiency에도 제약을 두어야 함."* Record conventions, not contents.

| Deliberately NOT stored | Why |
|-------------------------|-----|
| Full text / slide bodies / PDF pages | needs 100k+ SMB `open()`s — the exact banned traffic; `stat` only. "No text ≠ no interest." |
| Per-file bespoke fields (page runs, presenter label-runs, rationale, embeddings, synopses) | live in `archive_meeting_materials` / `archive_paper_synopses`; reached by **join on owner+date / canonical_id**, never duplicated. `nas_index` is a locator. |
| DOI/title behind a file open | `title_or_doi` is **filename-cheap only**; the ~79% of Context PDFs needing a first-page probe stay `NULL`. |
| Per-file rows under a `Code/` repo | **one pointer row per repo/dir** (§3.3b) — a repo is thousands of files; source/line-counts/embeddings are out. |
| Manuscript sections / abstract / full text | **one pointer row per file** — title + DOI is enough to route. |
| Contents of `fMRI_DICOM` / `SNUBIC` / `_USB` | `safe_walk` shallow-lists them; only the dir **name** is a row (`is_dir=true`). Millions of DICOMs never become rows. |
| Vendored toolboxes (`bads-master`, `mcmcstat`, `dynamic_bias`, `Gu_et_al`) | toolbox-prune list — not the researcher's code; not attributed, not indexed. |
| Recycle-bin shadows, `~$` lock stubs, dotfiles, AppleDouble | pruned/ignored at index time → zero phantom rows. |
| A second walk + a second watermark (D2's `archive_nas_watermark`) | collapsed into the index's `run_id` change feed — routing reads the DB delta, not the disk. |
| The `/Volumes/…` absolute path | volume drifts by mount order; store **share-relative**, resolve at read time → stable PK. |
| Ops/junk subtrees (`Server`, `Grant`, `group-volume`, …) | outside the four-subtree scope allow-list. |
| A `date` dimension for `experiment_code` | code files are not date-stamped (D3) — the column stays `NULL`; no expensive guessing. |

**Standing complexity total:** 3 new DB objects (`nas_index`, `nas_index_runs`,
`archive_nas_artifacts`) + reuse of `archive_meeting_materials`; 2 new scripts (`index_nas.py`,
`route_new_nas_files.py`) + 1 read-only MCP server; 2 catalog additions (`experiment_code`,
`manuscript`) as **data edits**; 2 prune knobs (toolbox, privacy). Everything else is reuse.

## 5. Phased implementation plan (with dependencies)

Each phase is behind the dry-run/`--apply` gate; the agent never holds prod-DB write.

- **P34.1 — Catalog conventions (no DB, no NAS).** Add `directories.experiment_code`,
  `directories.manuscript`, `lab_reports` note, toolbox-prune + privacy-exclude lists to
  `nas_catalog.json` (D3 §3, verbatim-shaped). *Dependency:* none. *Gate:* catalog edit only.
- **P34.2 — Migration.** `state/migrations/<date>_p34_nas_index.sql`: `nas_index`, `nas_index_runs`,
  `archive_nas_artifacts` (additive/idempotent/reversible). *Dep:* none (parallel with P34.1).
  *Gate:* `! run_migration`.
- **P34.3 — Indexer.** `scripts/archive/index_nas.py` (§1.2–1.5): scope allow-list, catalog-driven
  `kind`/owner/date, no-churn UPSERT, soft-delete, `run_id` stamping. *Dep:* P34.1 + P34.2. *Gate:*
  dry-run preview → `! index_nas.py --refresh --apply`. First run `--full` to seed.
- **P34.4 — Read-only MCP.** `scripts/mcp/nas_index_server.py` + `.mcp.json` entry (§2). *Dep:*
